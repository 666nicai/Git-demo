## 1. 题目要点覆盖对照

| 题目要求 | 本设计实现位置 |
|---|---|
| 用户基本信息：号码ID、昵称、出生、T龄(申请时间)、所在地 | `UserWRH`(继承 `BaseInfoWRH`) |
| QQ 与微博共享 ID | `QQAccountWRH::svcNo()` 与 `WeiboAccountWRH::svcNo()` 均返回同一主号 `owner_->mainNo()` |
| 微信独立 ID、可绑定 QQ | `WeChatAccountWRH`：独立 `wxNo_` + `boundQQ_`，`bindWxToQQ()` |
| 好友增/删/改/查 | `FriendBookWRH`(`add/remove/setRemark/find/list`) |
| 微X间共同好友 | `FriendBookWRH::commonWith()`，演示见 `demoCommonFriend()` |
| 微信添加 QQ 推荐好友 | `demoWeChatRecFriend()`/菜单好友功能7 |
| 预置群号 1001~1006 | 每类微X群均按 1001 起预置（QQ群1001/1002、微信群1001/1002） |
| 加入/退出/踢人/查成员 | `GroupWRH::requestJoin/inviteJoin/kick/quit`，`GroupMemberBookWRH` |
| QQ群可申请、微信群只能推荐/邀请 | 多态 `canApplyJoin()`：QQ=`true`，微信=`false` |
| QQ群临时讨论组(子群)、微信群不允许 | 多态 `canCreateSub()` + `createSubGroup()` |
| QQ群主为核心的管理员制度、微信群仅群主特权 | 多态 `hasAdminRole()/canSetAdmin()/canKick()` |
| 开通管理（可开通 N 个服务） | `UserWRH::openService/closeService` |
| 登录管理（一个登录，其它自动登录） | `UserWRH::login()` 置全部已开通账号 logged |
| 功能演示主菜单 | `PlatformWRH::run()` |

**多重关系要点**
- `BaseInfoWRH`（抽象基础类）被 `UserWRH` 继承复用，这正是题目“抽象基础类并被其它功能复用”。
- `MicroAccountWRH`→`QQ/微博/微信` 与 `GroupWRH`→`QQ群/微信群` 两个继承族，用**运行时多态（虚函数/纯虚函数）**表达微X产品之间的异同。
- `UserWRH` 1:N 组合 `MicroAccountWRH`（开通 N 个服务）；每个服务账号 1:1 拥有 `FriendBookWRH`（好友按服务划分，故可求“共同好友”、可“微信加QQ推荐好友”）。
- `GroupWRH` 1:1 拥有 `GroupMemberBookWRH`（成员及角色），成员指向 `UserWRH`。

## 3. 5 个技术层次实现说明

**第 1 层 · 基本功能**
- 主程序用顺序结构初始化，`PlatformWRH::run()` 提供“数字选择、0 返回上级”的主菜单与子菜单。
- 全流程用分支（`switch`）、循环（`while` 菜单）实现选择；各菜单可逐级返回到上一级。

**第 2 层 · 支持对象**
- 全部采用**类 + 对象**组织，每个类独立文件（.h/.cpp）。
- 构造函数/析构函数管理资源（如 `UserWRH` 析构释放开通的账号对象、`PlatformWRH` 析构释放用户与群对象）。
- `this` 指针、`operator==`（`FriendInfoWRH`）等对象机制均有体现。

**第 3 层 · 抽象封装**
- 用 `private/protected` 封装内部数据，只暴露操作接口（getter/setter/业务方法）。
- 抽象出 **基础信息类 `BaseInfoWRH`**、**账号信息抽象类 `MicroAccountWRH`**、**群抽象类 `GroupWRH`**。
- 用容器类封装集合：`FriendBookWRH`（好友容器）、`GroupMemberBookWRH`（成员容器），对容器内对象统一管理。

**第 4 层 · OO 多态**
- `MicroAccountWRH` 声明 `svcName/isSharedID/isWeChat/svcNo/show` 等纯虚接口，QQ/微博/微信各自覆写 → 同一“开通/展示”代码对不同微X给出不同行为。
- `GroupWRH` 用“模板方法 + 策略虚函数”实现：`requestJoin/kick/setAdmin/createSubGroup` 固定流程，是否可申请、谁可踢人、有没有管理员等由 `QQGroupWRH`/`WeChatGroupWRH` 多态决定 → 同一段群管理代码自动遵守 QQ/微信两套规则。

**第 5 层 · 优化提高**
- **文件 I/O**：`PlatformWRH` 构造时从 `platform_data.txt` 读入实例化（容器实例化时读入），析构时把容器写回文件（用户/开通/绑定/好友/群/群成员全量保存）；无文件时自动采用固化演示数据，菜单 6 可现场演示“保存→读回”。
- **数字菜单可返回上级**：所有子菜单选择 0 即可返回上级菜单。
- **可扩展性**：新增微X产品只需：① 在 `MicroType` 增加枚举；② 派生新 `MicroAccountWRH` 子类并覆写 4 个纯虚函数；③ 工厂处增加 new 分支。平台其余代码无需改动。
- **群管理模式动态可变**：`GroupWRH::modeTwin()` 能把 QQ 群变体生成为微信群对象（反之亦然），群号/群名/群主/全部成员**数据不受伤**，仅“管理规则/角色体系”随模式变化——对应题目“群的类型、管理模式可以随着平台的发展动态变化”。
- 所有类独立成文件、文件头带作者注释、类名统一带 WRH、关键处均有中文注释，并大量使用前向声明避免循环包含。
