# B 二叉树查找结点及父结点

- **平台**：PTA（吉林大学，作者：朱允刚）
- **分值**：20
- **限制**：题面未标出（同批 A 题为 200 ms / 20 MB，按同量级评估）
- **源文件**：[B 二叉树查找结点及父结点.cpp](B%20二叉树查找结点及父结点.cpp)（题面嵌在文件头 `/* */` 注释里）

## 题目描述

编写程序在二叉树中查找给定结点及父结点。二叉树结点的数据域值不等于 0 的整数。输入第 1 行为带空指针信息的二叉树先根序列（空指针用 0 表示），例如 `1 5 8 0 0 0 6 0 0` 表示：

```
        1
       / \
      5   6
     /
    8
```

### 输入格式

- 第 1 行：一组空格间隔的整数，即带空指针信息的先序序列；
- 第 2 行：整数 m，查询个数；
- 接下来 m 行：每行一个不等于 0 的整数 K。

m 不超过 100，结点数不超过 150000，高度不超过 6000，各结点数据值互不相等。

### 输出格式

输出 m 行，每行 1 个整数：结点 K 的父结点数据值；**无结点 K 或 K 无父结点（即 K 是根）则输出 0**。

### 样例

输入：

```
1 5 8 0 0 0 6 0 0
3
8
1
6
```

输出：

```
5
0
1
```

## 题意拆解

### 一、第一行有多长？不用管——序列自带边界

先序序列 + 空指针的编码是**前缀无歧义**的递归定义：

```
T = 0                      （空树）
T = v  T_left  T_right     （v ≠ 0）
```

从第一个 token 开始按这个文法解析：遇到非零数就造结点，然后**紧接着**解析它的左子树、再解析它的右子树；遇到 0 就返回。整棵树恰好用完第一行的所有 token，一个不多一个不少。

于是 A 题那个 `build()` 可以一字不改地搬过来，而且**不需要知道换行在哪**：`build()` 返回的那一刻，就是第一行结束的位置，后面直接 `cin >> m`。这比"先 `getline` 读一整行再拆"更稳——按行读会把程序绑死在"序列一定不折行"这个假设上，而这里的 300001 个 token 是很大的一行。

### 二、父结点不存，靠递归参数带下去

孩子指针是从父指向子的，结点里没有反向的 parent 指针。但遍历是从上往下走的，走到某个孩子时，"我是从哪个值下来的"这个信息就在调用栈上。所以把父值作为参数传下去即可：

```cpp
void dfs(Node *p, int par){   // par = 父结点的值
    ...
    dfs(p->l, p->v);
    dfs(p->r, p->v);
}
```

根结点的 `par` 传 0——题面要求"根结点无父结点输出 0"，和"结点不存在输出 0"是同一个值，正好共用一套约定，`dfs` 里不用任何特判。

### 三、一次遍历回答全部询问，而不是每个询问各搜一遍

| 做法 | 时间 | 额外空间 |
|---|---|---|
| 每个 K 各 DFS 一次找父结点 | O(n·m) ≈ 1.5×10⁷ | 0 |
| 建全表：值 → 父值（15 万项哈希表） | O(n) | 约 6~10 MB，逼近 20 MB 上限 |
| **只给待查的 ≤100 个值建表** | **O(n + m)** | **几十 KB** |

150000 个结点若全建 `unordered_map`，光桶数组加结点开销就吃掉一半内存预算；而真正需要的只有 m ≤ 100 个答案。所以：**读入询问时把 K 塞进哈希表当 key，DFS 途中对每个结点的值做一次 O(1) 查询，命中才记录父值**。

```cpp
if(ans.count(p->v)) ans[p->v] = par;
```

因为题目保证各结点数据值互不相等，一个值最多对应一个结点，表里 ≤100 项就足矣。

### 四、重复询问、不存在的值都自动正确

- 记录的是 `值 → 父值`，不是 `下标 → 父值`，同一个 K 问两遍也只是查同一项，天然不会漏答；
- 读入时先 `ans[K] = 0`（"当成没找到"），DFS 找到了再覆盖；始终没被覆盖的（树里没有这个 K）就保持 0 —— 正是题面要求。

## 参考代码

```cpp
#include<bits/stdc++.h>
using namespace std;

struct Node{
    int v;                      // 数据域
    Node *l,*r;                 // 左右孩子
    Node(int v):v(v),l(nullptr),r(nullptr){}
};

Node* build(){                  // 按带空指针的先序序列建树
    int x;
    if(!(cin>>x)) return nullptr;   // 输入结束
    if(x==0) return nullptr;        // 0 表示空指针,递归终点
    Node *p=new Node(x);
    p->l=build();                   // 紧接着的一段是左子树
    p->r=build();                   // 再紧接着的一段是右子树
    return p;
}

unordered_map<int,int> ans;     // 待查值 -> 父结点值,默认 0 即"无父/不存在"

void dfs(Node *p,int par){      // par 是父结点的值,根结点传 0
    if(!p) return;
    if(ans.count(p->v)) ans[p->v]=par;  // 只记录待查的那些值
    dfs(p->l,p->v);
    dfs(p->r,p->v);
}

int main(){
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    Node *root=build();         // 序列自带边界,建完正好停在第一行末尾
    int m; cin>>m;
    vector<int> q(m);
    for(int i=0;i<m;i++){
        cin>>q[i];
        ans[q[i]]=0;            // 先当作没找到,遍历时找到了再覆盖
    }
    dfs(root,0);                // 一次遍历回答全部询问
    for(int i=0;i<m;i++)
        cout<<ans[q[i]]<<"\n";
    return 0;
}
```

## 样例验证

序列 `1 5 8 0 0 0 6 0 0` 建出的树即题面图，查询 `8, 1, 6`：

| 结点 | dfs 到达时 | par 参数 | 是否被问 | ans 变化 |
|---|---|---|---|---|
| 1 | 第一个 | 0 | 是 | `ans[1] = 0` |
| 5 | 1 的左孩子 | 1 | 否 | — |
| 8 | 5 的左孩子 | 5 | 是 | `ans[8] = 5` |
| 6 | 1 的右孩子 | 1 | 是 | `ans[6] = 1` |

按询问顺序输出 `ans[8], ans[1], ans[6]` → `5, 0, 1`，与样例一致。

## 复杂度

- **时间** O(n + m)：建树每结点一次，dfs 每结点一次（含一次哈希查询），输出 m 次；150000 结点实测约 20 ms（含进程启动约 50 ms）。
- **空间** O(n)：150000 个结点 × 24 B ≈ 3.6 MB（`new` 的分配开销另计，约 6 MB），`ans` ≤ 100 项，递归深度 ≤ 树高 + 1 = 6001 帧，几十 KB 栈。

## 易错点

1. **别按行切分输入**。0 已经替你把每棵子树切好了，`build()` 返回就是第一行结束；反过来写"读一整行再 parse"会被"折行"这类判据坑到。
2. **根的答案是 0**，不要写成 -1 或者"特殊标记"，题面把"无父结点"和"结点不存在"都归到 0。
3. **0 不是结点值**。数据域保证 ≠ 0，这正是"0 当空指针"这个编码成立的前提；判断空指针只能判 `x == 0`，不能判 `x <= 0`（负数合法）。
4. **输出 m 行**，一行一个整数，不是空格分隔的一行。
5. **重复询问同一个 K**：用 `值 → 父值` 存结果，别用 `值 → 询问下标`，否则重复的 K 会覆盖掉前一个下标，让它永远输出 0。
6. **内存别铺全表**。20 MB 限制下，15 万项的 `unordered_map` 不划算，只给 ≤100 个待查值建表。
7. **递归深度**：树高 ≤ 6000，`build` 与 `dfs` 的递归栈约 6000 帧，1 MB 栈都够；但若把高度上限改到 10⁵ 级，就得换成显式栈的迭代版。
8. **树可能退化成链**：150000 个结点、高度 6000 说明数据里确实可能有长链，别假设树是平衡的。
